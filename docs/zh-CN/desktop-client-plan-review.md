# CyberStrikeAI 桌面客户端计划审查报告

> 审查对象：[桌面客户端二次开发计划 v1.3](desktop-client-development-plan.md)
> 审查日期：2026-07-31
> 审查结论：**计划已获用户批准，按 D0→D1 顺序执行**

## 1. 本次重新审查的原因

用户对“核心功能”边界做了最终收缩：本地 Terminal、WebShell、C2、机器人接入、多用户 RBAC 和远程服务模式不需要保留。因此 v1.2 中 R2 高风险能力和 R3 协作/远程能力的发布目标被撤销，v1.3 改为：

- R1：核心工作台。
- R2：API 文档与浏览器/Burp 对本地桌面实例的联动。
- 上述六类能力从桌面最终范围排除，不再作为“后续阶段”。

浏览器/Burp 插件联动未在用户的删除列表中，因此保留，但只允许连接本地随机回环端口，不延伸为远程服务模式。

## 2. 审查方法与证据

本次审查检查：

- 纳入与排除功能是否在目标、矩阵、工程阶段、工作包、测试和 DoD 中一致。
- Tauri v2 + Go sidecar 是否仍适配现有 Gin、SSE、WebSocket、SQLite 和本地工具模型。
- 是否保持 `cmd/server`、API、配置和用户数据兼容，避免因桌面端缩减而破坏现有服务端。
- 排除功能是否真正不初始化、不注册、不展示，且专用资源不进入安装包。
- Windows 与 macOS 是否有可验证的构建、签名、安装、升级和卸载路径。
- 编码是否仍受用户确认门禁约束。

证据来自当前分支的 `cmd/server/main.go`、`internal/app/app.go`、`internal/config/config.go`、`internal/security/`、`internal/c2/`、`web/templates/index.html`、`web/static/js/`、`config.example.yaml` 以及现有架构、安全、测试和发布文档。

## 3. 关键发现与修订结果

| ID | 等级 | 发现 | 计划处理 | 状态 |
| --- | --- | --- | --- | --- |
| R01 | 阻断 | Wails v3 仍是 Alpha，Wails v2 资源服务不完整支持当前 WebSocket/流式行为 | 改用稳定版 Tauri v2 + Go sidecar，WebView 直接加载本地 Gin URL | 已解决 |
| R02 | 阻断 | 当前 server 无法将端口 0 的实际地址交给桌面壳 | D2 增加 listener 注入、READY 协议和 readiness health gate | 已解决 |
| R03 | 阻断 | GUI 首启无法安全获得终端中输出的随机管理员密码 | D3 使用独立 bootstrap 窗口与受控 stdin，密码不进入 URL/参数/环境变量/日志 | 已解决 |
| R04 | 高 | Web 资源与业务数据依赖当前工作目录 | Web 资源嵌入 core，数据使用平台应用数据目录绝对路径 | 已解决 |
| R05 | 高 | SQLite 使用 `go-sqlite3`/CGO，交叉编译不能代替目标平台验收 | Windows x64、macOS arm64/x64 分别在对应 runner 构建并启动测试 | 已解决 |
| R06 | 高 | 排除桌面功能若只隐藏菜单，可能仍被直接 URL/API 调用 | Desktop 能力清单同时限制初始化、路由注册、导航和设置，D9 专门测试不可达 | 已解决 |
| R07 | 高 | 排除 C2 但仍打包 Payload 模板会扩大安装包和终端防护误报面 | 任何桌面版均不打包 C2 Payload 模板，发布物扫描作为 DoD | 已解决 |
| R08 | 高 | “不需多用户 RBAC”可能被误实现为免登录管理员 | 仅排除多用户管理 UI/API；单管理员登录、授权中间件、HITL 和审计继续保留 | 已解决 |
| R09 | 高 | 为桌面版删除共享 Go server 中的排除模块会破坏现有 CLI | 不做服务端破坏性裁剪；使用 desktop 配置画像和路由/能力清单隔离 | 已解决 |
| R10 | 高 | 本地随机端口使浏览器/Burp 难以发现实例 | R2 使用受控发现机制；发现信息不含凭据，实例重启后失效 | 已解决 |
| R11 | 高 | 全量打包第三方攻防工具会显著增加供应链和安装包风险 | 保持现有“定义随项目、可执行文件由系统安装”边界，桌面端提供诊断与指引 | 已解决 |
| R12 | 高 | 默认资源升级可能覆盖用户修改 | 使用带 SHA-256 的 resource manifest，冲突并列保留 | 已解决 |
| R13 | 高 | 旧实例直接复制 SQLite 可能遗漏 WAL/SHM 或得到不一致副本 | D6 使用一致性备份、暂存迁移和原子切换 | 已解决 |
| R14 | 高 | WebView 如可导航任意网页，会把本地高权限 UI 暴露给不可信内容 | 只允许本次回环源，外链交系统浏览器，禁用通用 Shell/文件 IPC | 已解决 |
| R15 | 中 | 只在最后做一次发布验收无法保证分阶段交付 | D7 是 R1 发布门禁，D9 是 R2 完整版发布门禁 | 已解决 |
| R16 | 中 | Windows WebView2/WKWebView 差异和 Windows 首启 sidecar 扫描可影响启动与协议行为 | D1 先在三个一级架构验证 REST/SSE/WS/生命周期，发布前签名并记录终端防护结果 | 已纳入门禁 |

## 4. 范围一致性审查

### 4.1 纳入范围

R1 包含：登录/初始化、AI 通道、仪表盘、对话/单多 Agent/HITL、工具/MCP、工作流、项目、资产/信息收集、漏洞、任务、知识库、Agent 角色/Skills/Agents、文件、监控、审计、设置、国际化和主题。R2 增加 API 文档和浏览器/Burp 本地联动。

### 4.2 排除范围

| 能力 | 审查后的 desktop 处置 |
| --- | --- |
| 本地 Terminal | 不展示设置入口，不适配 PTY/WebSocket，不验收 |
| WebShell | 不注册导航与 desktop 路由 |
| C2 | 不初始化服务，不注册导航/路由，不打包 Payload 模板 |
| 机器人 | 不初始化服务，不显示配置 |
| 多用户 RBAC | 不注册多用户管理页和 API；保留单管理员登录与授权链 |
| 远程服务模式 | 不设计 endpoint 切换 UI，桌面端始终托管本地 sidecar |

`web/templates/index.html` 当前有 28 个业务页面面板。排除 WebShell、平台 RBAC 和六个 C2 页面后，desktop 最终验收 20 个纳入页面；Terminal 和机器人是设置内能力，应额外验证其控件不显示。

## 5. 架构、安全与生命周期审查

页面、REST、SSE 和 WebSocket 仍由本次 Go core 的同一随机回环源提供，因此不需要重写现有前端 API 调用或将业务逻辑迁入 Rust。Tauri 只拥有窗口、单实例、sidecar 生命周期、安装包和更新入口。

桌面壳拥有 core，core 拥有外部 MCP、Agent 任务、HTTP 服务和数据库。退出顺序可取消、可等待，超时后才强制终止。机器人、C2 和 Terminal 不是 desktop 进程树的验收对象，反而要证明它们从未被初始化。

安全控制仍包括：本地单管理员登录、权限中间件、HITL、审计、凭据库、WebView 导航/CSP/capability allowlist、签名更新、SBOM 和发布物敏感内容扫描。“本地”和“单用户”不是免鉴权的理由。

审查结论：架构在范围收缩后更简单，但 D1 技术验证仍是不可跳过的门禁。

## 6. 平台、数据与测试审查

- Windows x64、macOS arm64 和 macOS x64 分别构建和安装，不用单平台结果代替。
- 数据导入使用白名单、SQLite 一致性备份、暂存预检和原子切换；旧配置中的排除开关被忽略并写入报告。
- R1 和 R2 都需要原生安装、升级、卸载、重装、签名和数据保留证据。
- D9 对 20 个纳入页面逐项验收，并对 8 个排除页面和两类设置内排除能力做不可达测试。
- 浏览器/Burp 联动必测未登录、错误来源、发现信息过期、实例重启和 CORS 拒绝。

审查结论：范围、数据和测试现在一致。实施时若缺少某个一级平台的真实设备或 runner，不能用其他平台的绿色结果代替。

## 7. 剩余风险与决策点

| 风险 | 概率 | 影响 | 处理方式 | 决策点 |
| --- | --- | --- | --- | --- |
| Tauri 外部本地 URL 在 WebView2/WKWebView 的协议或导航行为存在差异 | 中 | 高 | D1 同时验证 REST/SSE/WS/导航/下载 | D1 结束 |
| Windows 首启时 WebView2 准备或终端防护扫描 sidecar 导致延迟 | 中 | 中 | 显示可观测启动状态，区分 READY 超时/被隔离/进程崩溃，签名发布物 | D1/D7 |
| Rust 工具链增加维护负担 | 中 | 中 | Rust 仅限壳层，不迁移业务逻辑 | D1 评估代码量 |
| macOS/Windows 签名证书无法及时提供 | 中 | 高 | 开发包可继续，R1/R2 正式发布被 D7/D9 阻止 | D7 前 |
| 桌面能力清单与共享 server 新增路由后发生漂移 | 中 | 高 | CI 生成路由/页面清单并对纳入/排除集合做差异检查 | 每次发布 |
| 插件实例发现机制无法同时满足易用性和无凭据泄漏 | 中 | 高 | D8 先完成手动受控联动，自动发现仅在安全门禁通过后交付 | D8 结束 |

剩余风险均有明确的验证阶段和停止条件，不需要在编码前通过猜测消除。

## 8. 计划质量结论

审查结论为：**有条件通过**。

用户对功能纳入/排除范围的最新决策已完整写入 v1.3。用户于 2026-07-31 回复“按计划开始”，同时接受下列三项实施假设：

1. 使用稳定版 Tauri v2 + Go sidecar。
2. 首发一级架构为 Windows x64、macOS arm64 和 macOS x64。
3. 第三方攻防工具不随主安装包全量内置，桌面端提供诊断与安装指引。

编码门禁已经解除，但仍必须从 D0/D1 开始，不得跳过技术验证直接大规模改造。
